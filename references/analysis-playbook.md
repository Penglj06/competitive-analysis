# 竞品分析 · Playbook（执行手册）

本文件是 `competitive-analysis` skill 的详细执行手册。SKILL.md 只放判定规则与路由，
每一步的完整 Prompt 模板、细则、证据标准都放在这里。

> **语言**：本手册以中文书写，仅为文档语言。实际产出（报告、分析结论）的**语言跟随用户**——
> 用户用中文则输出中文，用其他语言则用其语言；无法判断时默认中文，并可询问或提供双语选项。
> 下方 Prompt 模板中的中文示例句，按用户语言等比替换即可。

## 一、证据分级标准（全程标注，唯一标准）

| 等级 | 定义 | 判据 | 报告标注 |
|---|---|---|---|
| **一手** | 真体验 / 真访谈 / 真数据 | 本人或用户真实注册使用过；真实用户访谈；拿到真实数据 | 「一手」 |
| **走查** | 实时访问页面所见 | 用环境提供的页面访问能力实时打开竞品页面看到的实际功能/文案/定价 | 「走查」+ 时间 |
| **公开** | 官方公开信息 | 官网文案、帮助文档、媒体报道、财报、公开文档、搜索摘要 | 「公开」+ 来源 |
| **推断** | AI 推测 | 基于上述信息的推演 | 「推断」+ 附「用什么公开信号可佐证/证伪」 |

**推断项不得当作事实陈述**。写报告时推断结论必须带显式的「（推断）」标记。

> **「走查」与「一手」的边界（易混淆）**：走查只能看到公开可访问的页面，
> 看不到登录后的真实使用、真实数据和真实用户反馈。因此：
> - 「页面展示了什么功能/文案/定价」→ 走查可作准
> - 「用户真实体验如何/效果怎样/内部数据多少」→ 走查**看不到**，只能标「未验证/无数据」
> - 走查截图是可靠的「页面证据」，但不是「产品好用/有效」的证据

> **官方自述数字 ≠ 独立核验数字**：官网/宣传页的规模数字（用户数、文献量、期刊数、
> 融资额等）常含营销口径放大。引用时标「官方自述，未独立核验」；发现同一指标不同口径
> （官网 vs 媒体 vs 财报）时显式列出差异与可能原因（时间点 / 营销口径 / 统计口径），
> 不替用户选一个当真。**官方数字与第三方数字冲突时，如实并列，不下「谁对谁错」的结论。**

## 二、第 1 步 · 明确目标的 Prompt 模板

```
你现在是一位资深产品经理。我准备做一次竞品分析，请你先不要急着分析竞品，
先帮我明确这次分析的目标。按以下结构输出：

1. 这次分析可能要解决什么产品问题？
2. 应该重点关注哪些维度？
3. 哪些信息必须收集？
4. 哪些信息只是参考，不应该影响决策？
5. 最终应该输出什么结论？
6. 这次分析如果做完，应该帮助团队做什么决定？

背景：【粘贴当前产品问题 / 需求背景 / 老板要求】
```

**资源分配默认值**（可让用户调整）：

- 直接竞品：2-3 个，深看（全流程）
- 间接竞品：3-5 个，看单点（流程 / 交互 / 商业模式）
- 跨行业参考：2-3 个，只取一个能力

```

1. 目标用户是谁？

3. 它把哪些事情做得很重？
4. 它把哪些事情刻意简化了？
5. 它可能牺牲了什么体验？
6. 它的商业化或转化设计在哪里？

竞品信息：【粘贴】
```

**关键约束**：删除原方法里的「它最想提升的指标可能是什么」这一问。竞品的

公开融资新闻、公开财报）并标来源与时间。

## 七、第 6 步 · 借鉴/照抄二分的模板

```
请基于上面的竞品分析，帮我区分两类，输出成表格：

一、值得我们借鉴的点（说明：借鉴点是什么 / 解决什么问题 / 为什么适合我们 / 落地如何改造）
二、不能直接照抄的点（说明：竞品怎么做的 / 为什么不能直接抄 / 照抄的风险 / 我们的替代方案）
```

**判断「能不能抄」的六个底层变量**（用户规模、业务阶段、数据能力、品牌心智、
商业模式、资源投入）用于评估迁移风险：低风险交互细节可直接采用，中风险方案需本地化改造，高风险商业或增长机制不直接复制。

## 八、第 7 步 · 决策输出的模板

```
请基于以上竞品分析，输出产品决策建议，分三类：

一、建议立即优化（优化项 / 原因 / 预期收益 / 实现复杂度）
二、建议先验证（需要验证什么 / 验证方式 / 成功标准）
三、不建议照抄（竞品做法 / 我们不做的原因 / 替代方案）

最后请给出：
1. 本次竞品分析的核心结论
2. 对当前产品最重要的 3 个启发
3. 下一步产品行动建议
4. 可以写入 PRD 的内容
```

> 原文模板有「300 字结论」要求，本 skill 删去字数要求，改为「核心结论」，
> 避免滑回「A 更完整、B 更简洁」的套话。

## 九、一次性完整 Prompt（仅在用户坚持时使用）

> 默认**不推荐**使用。分步走、每步确认再进下一步，效果远好于一次要结果。
> 若用户坚持一次性输出，未确认竞品标为候选，缺失信息列为假设；推断或低强度公开证据原则上只能进入“先验证”。

```
你现在是一位资深产品经理，擅长竞品分析、产品策略拆解和产品决策建议。
请按以下结构输出，且每条关于竞品的结论都要标注证据等级（一手/公开/推断）：

一、分析目标（解决什么问题 · 支撑什么决策）
二、竞品选择（直接/间接/跨行业 + 各类看什么）
三、竞品核心流程拆解
四、功能与体验对比（入口·场景·流程·操作成本·闭环·体验·业务目标）
五、产品策略分析（目标用户·核心场景·转化设计·取舍，不编指标）
六、可借鉴点（含如何改造）
七、不可照抄点（含风险）
八、产品决策建议（立即优化/先验证/不建议照抄）
九、核心结论（最大发现 + 下一步最该做什么）

我们的产品背景：【粘贴】
当前产品问题：【粘贴】
竞品信息：【粘贴】
```

## 十、深度走查操作指引（把证据从「公开」升级为「走查」）

> 直接竞品可访问时，优先走查；公开资料只作补充与交叉验证。

### 走查前：核对竞品主体（易踩坑，硬性）

用户给的链接**未必是要分析的竞品本身**——同名站、仿冒站、蹭名站、第三方平台上的
同名 Agent 很常见。走查前先核对「这个 URL 的域名/主体是不是用户要分析的那个竞品」：

- 域名明显对不上（用户说某公司产品，链接却挂在某 Agent 平台子域如 `<第三方智能体平台>/site/...`）
  → 先用宿主的用户提问能力核对，**不要直接访问**，避免在错误站点上空转。
- 核对方式：确认域名与页面主体是否与目标竞品一致，或直接问用户「你要分析的是不是这个主体的产品」。
  **只使用用户提供的 URL，不自行扩展或替换目标。**
- 实测教训：用户给的某产品链接挂在第三方智能体平台下，与正牌官网是两回事，
  先核对才没在错误站点上空转。

### 何时走查

- 直接竞品**可访问**、**环境已具备页面访问能力**、且**用户已同意** → 走查
- 竞品有登录墙 / 付费门槛 / 地区限制 → 标注「无法走查」，降级公开资料
- 环境**未提供**页面访问能力 → **不安装依赖**，直接降级公开资料

### 走查预算（默认）

- **深走查 1-2 个直接竞品**：逐页走核心流程（入口→引导→任务→付费→复用）
- **其余竞品轻走查**：只开首页 + 定价页，抓定位 slogan、核心能力、定价档位
- **不追求全量深走查**：走查有环境与时间成本，全量走查耗时长、边际收益低

### 走查流程（使用环境已提供的页面访问能力）

> **前置（硬性）**：本 skill **不安装、不配置**任何浏览器工具，**不提供安装命令**。
> 浏览器能力应由使用者在受控工作区中自行预置；若确需安装，须**先取得用户同意**、
> 使用**固定且经审阅的版本**做**项目本地安装**（**禁止任何全局安装**），
> 并在隔离的浏览器配置与最小权限下运行。**环境未提供该能力时，直接走公开资料路径，
> 不要为了走查而安装任何东西。**

若环境已提供页面访问能力，按其**既有用法**逐页操作核心流程。通用序列如下
（具体命令依宿主能力而定，本文件不给出可直接复制的安装/执行脚本）：

1. 打开目标页面 → 等待「页面加载完成」（页面慢或空白时，不要死等「网络空闲」）；
2. 抓取页面文本与其上的可交互元素，作为「走查所见」的原始记录；
3. 关键页面保存截图（PNG），供报告配图；
4. 逐页走核心流程（入口→引导→任务→付费→复用），定价页单独记录；
5. 结束后**关闭会话**，避免残留进程。

**走查纪律**：只用**用户提供并已核对主体**的 URL；**不输入任何个人账号凭据**；
在隔离的浏览器配置（干净 profile）下进行，不继承个人浏览数据。

### SPA 降级与空数据判断（易踩坑，硬性）

很多现代站点是单页应用（SPA），等待「网络空闲」可能一直挂起或拿到空内容。走查时：

1. 等待超时 → 降级为只等「页面加载完成」；
2. 拿不到内容时先探测页面**正文长度**与**脚本 / 图片数量**；
3. 正文极短（如 < 200 字符）→ 动态渲染还没出内容；
   正文出现 `{"status":0,"data":{}}` 之类接口空返回、或脚本/图片数为 0
   → 是**登录墙 + 动态渲染**，未登录拿不到真实数据；
4. 命中登录墙 → 如实标「无法走查」，降级为宿主可用的公开资料搜索，报告证据边界里说明；
   要不要换走查目标（如正牌官网）先问用户，别自行替换。

> 实测：某智能体平台 agent 详情页对未登录访问返回 `{"status":0,"data":{}}`，
> HTML 仅百余字符、无脚本无图片，就是登录墙的典型信号。

### 走查要记录什么

对应第 3 步的流程节点，逐项记录**实际看到的**：

- 入口、新手引导、核心任务开始方式
- 关键页面/模块、用户操作路径、系统反馈方式
- 结果输出方式、复用/留存设计、付费/转化节点

每项产出都标「**走查**」（不是「一手」），并附截图（PNG）作为报告配图。

### 走查纪律

- 走查结果与公开资料冲突 → 以走查为准，并注明
- 走查是「记录实际」，不是「推断设计意图」——设计意图仍标【推断】
- 竞品若需注册才能看核心功能，如实说明「仅走查到公开可见部分」
- **「走查」≠「一手」**：走查只看到公开页面，看不到登录后真实使用/真实数据/用户反馈。
  涉及「用户真实体验/效果/内部数据」的结论，标「未验证/无数据」，不得拔高成「一手」
- **定价/版本类信息务必走查核对**：公开资料（WebSearch 快照）常含过时或错误的定价档位
  （实测：某学术工具公开资料有「$12 Plus 档」，走查确认当前是 Basic Free / Pro / Team /
  Enterprise 定制，无 Plus 档）。凡涉及价格、档位、数据规模（如「索引 N 篇论文」）
  的硬数字，以走查页面为准，不要照抄搜索摘要。

## 十一、PNG 示意图绘制指引（已端到端验证）

> 图表进 Word 必须用 PNG。SVG 进不了 Word。
> 以下方案已端到端验证通过：HTML 含 `<img src="本地 PNG">` → html-to-docx → docx 内有图片。

### 何时用示意图 vs 走查截图

- **走查截图**（首选）：走查时保存的关键页面截图（PNG），是最有证据力的配图，又满足含图要求
- **示意图**：竞品格局分层图、差异化定位图、对比图、流程图等结构化图（无现成截图可用时）

### 用 Pillow 画中文 PNG（macOS）

```python
from PIL import Image, ImageDraw, ImageFont

# 中文字体路径（macOS 系统自带，无需安装）
font_path = '/System/Library/Fonts/Hiragino Sans GB.ttc'
font_title = ImageFont.truetype(font_path, 16)
font_body = ImageFont.truetype(font_path, 13)

img = Image.new('RGB', (680, 380), (250, 250, 247))  # 米色背景
d = ImageDraw.Draw(img)
d.text((20, 12), '竞品格局（我方产品视角）', font=font_title, fill=(30, 30, 30))
# 圆角矩形卡片：d.rounded_rectangle([x1,y1,x2,y2], radius=8, fill=..., outline=..., width=1)
# 文本：d.text((x, y), text, font=..., fill=...)
img.save('/path/to/chart.png')
```

**支持能力**（端到端验证过）：
- 中文文本不乱码（Hiragino Sans GB.ttc 渲染清晰）
- 中英混合文本（"我方产品（学科范式 + 资源底座）"渲染正常）
- 圆角矩形 + 多色填充（用于分层卡、表格、对比块）
- 横线/分隔线
- PNG 输出（≤16cm 宽，html-to-docx 自动缩放）

**不支持**（别尝试）：
- 箭头、流程连接线（要画箭头/连线，用 matplotlib 或手写 SVG→PNG）
- 复杂图表（柱状/折线/饼图）—— 用 matplotlib，更专业

### 何时用 matplotlib（需要箭头或统计图）

```python
import matplotlib.pyplot as plt
import matplotlib
# macOS 中文字体
matplotlib.rcParams['font.sans-serif'] = ['Hiragino Sans GB']
matplotlib.rcParams['axes.unicode_minus'] = False

fig, ax = plt.subplots(figsize=(8, 5))
# ... 画图
plt.savefig('/path/to/chart.png', dpi=150, bbox_inches='tight')
```

### HTML 引用 PNG 进 Word

```html
<p><img src="/abs/path/to/chart.png" alt="图表说明" width="600"></p>
```

- 必须用**绝对路径**，相对路径可能找不到
- `width` 单位是 CSS 像素，docx 内会自动按比例缩放（最长边 16cm）
- 多个图就 `<img>` 多次

### 降级路径

- Pillow/matplotlib 不可用 → 用走查截图顶替
- 都没有图 → Markdown 表格当图 + 报告头注明「本版无图，详见表格」

## 十二、跨场景适配提示

这套工作流是通用调研框架，换掉「竞品」可套到：

- **技术选型**：拆架构机制、反推设计取舍、迁移判断
- **benchmark 调研**：拆评测方法、反推评测意图、迁移到自己的评测
- **学术工具/文献综述**：拆研究流程位点、反推方法取舍
- 用户访谈整理不属于本 skill 的自动适用范围，应使用访谈研究类 skill

**学术产品（AI4S）特别提示**：学术产品的公开指标（DAU、留存）几乎查不到，
第 5 步强行反推指标会更假。改为反推「它服务的研究/业务流程位点是哪一段」——
这个从产品形态能观察到，比编指标可靠。
